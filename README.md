# FarmWar / FoodWar

FarmWar 是一款使用 Godot 4 开发的多人团队对抗农场游戏。玩家需要在 Creston Town 中种植、采集、烹饪、运输和交付物资，同时使用武器、载具、无人机及各类工具与另一支队伍竞争。

项目当前处于持续开发阶段，游戏内工程名称仍为 `FoodWar`。

## 当前内容

- 单人游戏与多人游戏流程
- 红蓝双方队伍、队伍金钱与任务奖励
- 农作物种植、成熟、收获及自然资源采集
- 树木、矿石、稀有巨大作物和资源刷新
- 烹饪设备、菜谱、成品菜与队伍库存
- 玩家背包、装备、载重和耐久系统
- 枪械、魔法武器、投掷物及可放置工具
- 载具、CargoCar 货运箱存储与 CargoArea 交付
- 家禽、牲畜、Chop 养殖设施和野生动物
- 黑熊 FSM、战斗效果和服务器权威伤害
- 昼夜循环、太阳、月亮、云层和夜间路灯
- Remote 设备、无人机与摄影无人机
- F12 无 UI 截图和摄影无人机截图/录像

## 开发环境

- Godot `4.6.3` Mono
- 渲染器：Forward+
- 设计分辨率：`1920 x 1080`
- 物理引擎：Jolt Physics

建议使用与工程配置相同或更新的 Godot 4.6 Mono 稳定版本。

## 启动项目

1. 克隆仓库：

   ```bash
   git clone https://github.com/2397786244/FarmWar.git
   ```

2. 使用 Godot 4.6 Mono 导入项目根目录中的 `project.godot`。
3. 等待 Godot 完成首次资源导入。
4. 运行主场景，从主菜单选择单人游戏或多人游戏。

首次导入生成的 `.godot/` 目录不需要提交到 Git。

## 数据配置

主要物品和玩法参数保存在 `data/`：

| 文件 | 内容 |
| --- | --- |
| `tool_definitions.json` | 武器、工具、投掷物和可放置道具 |
| `equipment_definitions.json` | 背包、胸甲和护腿装备 |
| `ingredient_definitions.json` | 农产品、原材料、矿石等物品 |
| `dish_definitions.json` | 成品菜定义 |
| `recipe_definitions.json` | 厨具菜谱 |
| `auto_cooker_recipe_definitions.json` | 自动做菜机菜谱 |
| `extractor_recipe_definitions.json` | 食材提取器配方 |
| `stand_mixer_recipe_definitions.json` | 搅拌机配方 |

## 多人架构

多人游戏中的关键玩法由服务器权威处理，包括角色和动物伤害、资源状态、载具、工具、库存、任务与奖励。客户端负责提交操作请求并渲染服务器同步的视觉代理。

涉及共享状态的新功能应同时检查：

- 单人本地权威路径
- 多人服务器权威路径
- 远端客户端视觉同步
- 断线、死亡和节点销毁后的状态释放

## 后续开发路线图

### 第一阶段：完成 Creston Town 商店

- 完成 `Livestock` 商店，用于购买养殖动物及相关商品。
- 完成 `CraftWorks` 商店，用于出售农场生产和工业制作需要的商品。
- 复用现有 FoodCar、GunStore 的商店区域、交互提示、队伍金钱结算和购买入包流程；商品清单、价格及描述继续采用数据配置。

这一阶段以接入既有商店框架为主，但仍需检查背包容量、唯一物品限制、多人服务器扣款及远端商店状态。

### 第二阶段：农场工业制品

- 为胸甲、护腿和背包增加专门的制作操作台，不再仅依赖商店或调试指令获得。
- 建立类似厨房的工业操作间，并逐步加入不同用途的加工台、装配台和制作流程。
- 接入载具升级使用的工业道具与元件，包括已经完成模型制作的电池组、齿轮等；后续需要完成物品注册、图标与手持/掉落显示、制作配方以及载具升级消耗规则。
- 将装备配方、原材料、制作时间和产物状态数据化；制作时优先使用玩家背包材料，并按照最终规则衔接队伍库存。
- 操作台沿用服务器权威排他锁、制作进度同步、玩家断线/死亡释放和重新打开 UI 后恢复进度的规则。

这一阶段需要新增完整的工业配方与生产状态体系，同时保证装备耐久、属性和实例数据在制作、掉落、拾取及多人同步中保持不变。

### 第三阶段：战局 UI 与 3D 主界面

- 继续整理战局 HUD 的层级、尺寸、配色和信息密度，减少遮挡并统一玩家、载具及 Remote 设备的信息区域。
- 将当前纯色主界面替换为实时 3D 展示场景，例如农场角落中的 Farmer 手持肥料喷洒器。
- 主界面展示内容可从配置中随机选择：角色、手持道具、附近载具或专属设备组成一个主题镜头，例如 Rider 与脚边的自爆小车。
- 主标题及“单人游戏”“多人游戏”等入口移动到左下角，右侧和画面主体用于展示角色、环境、灯光与轻量动画。
- 3D 展示场景应与正式游戏世界隔离，限制高成本逻辑，仅运行必要动画、镜头和环境效果，并为不同分辨率保留稳定构图。

这一阶段可拆成“战局 HUD 调整”和“3D 主菜单”两个子阶段。建议先建立数据驱动的展示场景模板，再逐个增加角色主题组合。

### 复杂度排序

1. **Creston Town 商店：低到中等。** 主要复用已有商店系统，工作集中在商品配置、场景接入和多人购买校验。
2. **战局 UI 与 3D 主界面：中到高。** 后端改动有限，但需要较多响应式布局、镜头构图、灯光、动画和性能调优。
3. **农场工业制品：高。** 涉及新生产系统、多个操作台、配方与实例状态，还需要完整覆盖服务器权威和多人同步。

## 开发说明

- 不要提交 `.godot/`、导出构建、截图、临时文件或 IDE 本地设置。
- `builds/` 只用于本地导出，不属于源码仓库。
- 新增可进入背包的物品时，应同步注册对应配置和图标/模型解析。
- 新增伤害目标时，应同时检查子弹、炮弹、爆炸、命中提示和多人同步。
- 新增可交互设施时，应处理距离关闭、`Esc` 关闭和服务器排他锁释放。
