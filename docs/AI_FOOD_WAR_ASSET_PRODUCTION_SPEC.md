# Food War 3D 资产 AI 制作与职业设计规范

版本：1.0  
用途：把本项目的建筑、食物、农作物、厨具和手持工具建模任务迁移给其他 AI 或 Blender 自动化代理。  
目标引擎：Godot 4.x  
交付格式：Blender Python 脚本、GLB 模型、PNG 预览图。

---

## 1. 项目视觉定位

Food War 是一款轻量级多人农场厨房对抗游戏。画面需要同时满足：

- 第一眼轻松、明亮、友善，而不是军事写实。
- 玩家在快速移动时仍能识别土地、作物、厨具和武器用途。
- 红蓝双方清晰，但队伍颜色不能淹没物体自身的功能颜色。
- 独立开发者可以持续用 Blender Python 批量扩展资产。
- 不依赖手绘贴图、雕刻高模、烘焙流程或复杂骨骼。
- 模型可以在中低配置设备上大量同时出现。

### 1.1 核心风格关键词

```text
stylized low-poly
chunky silhouette
soft-toy proportion
clean color blocking
friendly competitive
rounded single-segment bevel
readable at gameplay distance
modular
procedurally reproducible
```

中文概括：

- 卡通低面数。
- 轮廓粗壮，结构适度夸张。
- 大色块、少材质、少零件。
- 边缘略圆，但保留低面数切面感。
- 不追求真实世界精密结构。
- 功能优先于装饰。

### 1.2 禁止出现的视觉方向

- 写实军事武器、脏污血腥、尖锐恐怖造型。
- 大量螺丝、细管、导轨、刻字等远处不可见细节。
- 依靠4K贴图或法线贴图才能成立的模型。
- 过度圆滑、像高模玩具渲染的曲面。
- 大面积纯黑、纯白或高强度自发光。
- 与《植物大战僵尸》《斯普拉遁》等作品角色或武器的一比一复刻。

可以借鉴“容易辨认、夸张有趣”的设计原则，但必须形成 Food War 自己的轮廓和配色。

## 2. 全局技术规范

### 2.1 Blender版本与运行方式

脚本必须能在干净环境中执行：

```powershell
blender.exe --background --factory-startup --python generate_asset.py
```

脚本不得依赖：

- 当前打开的 `.blend` 文件。
- 用户手动选中的对象。
- 外部插件。
- 本机绝对贴图路径。
- 未明确安装的第三方 Python 包。

### 2.2 单位与尺寸

```python
scene.unit_settings.system = "METRIC"
scene.unit_settings.scale_length = 1.0
```

Blender 1单位视为1米。

推荐尺寸：

| 类型 | 推荐尺寸 |
|---|---|
| 单块建筑墙 | 宽2m、高2.5m、厚0.18–0.25m |
| 普通门 | 宽1.0–1.3m、高2.0–2.3m |
| 厨房工作台 | 宽1.2–1.8m、高0.85–1.1m |
| 双门冰柜 | 宽1.5–2.0m、高2.0–2.4m |
| 单株小作物 | 高0.25–1.2m |
| 南瓜、西瓜等果实 | 直径0.25–0.55m |
| 单手工具 | 长0.8–1.3m |
| 炮塔 | 高0.8–1.4m |

模型尺寸应优先服务游戏可读性，可以比现实物体略粗、略大。

### 2.3 坐标与朝向

- `+Z`：上方。
- 建筑正面：Blender 本地 `-Y`。
- 厨具正面和可交互面：本地 `-Y`。
- 枪口和工具发射方向：本地 `-Y`。
- 植物根部位于 `Z=0`。
- 建筑、厨具原点位于底部中心。
- 手持工具原点位于握持区域附近，枪口位置由 Godot `Marker3D` 定义。

导出使用：

```python
bpy.ops.export_scene.gltf(
    filepath=output_path,
    export_format="GLB",
    use_selection=True,
    export_apply=True,
    export_yup=True,
)
```

推荐只导出明确选择的可见根节点及其子对象，避免测试物体、灯光或碰撞壳混入 GLB。

### 2.4 Transform硬性规则

导出前：

```python
bpy.ops.object.transform_apply(
    location=False,
    rotation=False,
    scale=True,
)
```

必须满足：

- 所有轴缩放均大于 `0.000001`。
- 不存在 `NaN`、`Infinity`、奇异 Basis。
- 不通过负缩放制造镜像；镜像后应用变换并重新计算法线。
- 根节点位置和旋转应保持简单、可预测。
- 不对拥有子对象的根节点反复应用不明确的非均匀缩放。

## 3. 统一形体语言

### 3.1 基础图元

优先使用：

- Cube：建筑、机身、工作台、门框、面包主体。
- 6–10边 Cylinder：枪管、锅、果实、按钮、罐体。
- Icosphere：水果、汤中蔬菜、树冠。
- Plane：玻璃、队伍标记、特殊透明表面。

圆柱建议：

| 用途 | 顶点数 |
|---|---:|
| 小按钮、把手连接件 | 6 |
| 枪管、锅、普通罐体 | 8 |
| 主要圆形轮廓 | 10 |
| 近景英雄部件 | 最多12 |

### 3.2 倒角

主要硬表面使用一段倒角：

```python
modifier = obj.modifiers.new("SingleSegmentBevel", "BEVEL")
modifier.width = 0.02
modifier.segments = 1
```

- 建筑模块：通常 `0.015–0.04m`。
- 厨具：通常 `0.015–0.035m`。
- 小工具：通常 `0.008–0.025m`。
- 食物：使用低边数圆形和少量倒角，不要变成完全光滑高模。

### 3.3 轮廓优先

所有资产按以下顺序制作：

1. 使用1–4个大体块完成黑色剪影。
2. 从游戏距离检查能否认出类别。
3. 加入一个最重要的功能识别结构。
4. 最后加入少量连接件和点缀。

缩略到约100像素高度时仍应能够辨认资产用途。无法辨认的小细节应删除或增大。

### 3.4 部件连接

- 看似连接的零件必须真实接触或轻微穿插 `0.01–0.04m`。
- 不允许把手、按钮、烟囱、枪管、果实悬浮。
- 不创建无意义的内部结构。
- 两块不同颜色的装饰板可以略微离开主体，但必须有清晰层级和连接关系。

## 4. 配色系统

### 4.1 全局色彩原则

每个资产使用3–6种材质：

- `60%–75%` 主体色。
- `15%–25%` 深色结构色。
- `5%–15%` 功能强调色。
- 必要时少量中性色。

不使用贴图。使用 Principled BSDF 的：

- Base Color
- Roughness
- Metallic
- 必要时少量 Emission

大部分表面：

```text
Roughness = 0.55–0.85
Metallic = 0.0
```

金属把手、锅沿、枪口：

```text
Roughness = 0.35–0.62
Metallic = 0.35–0.75
```

### 4.2 推荐基础调色板

以下颜色用于统一视觉，不要求每个资产全部使用。

### 4.3 队伍色规则

红蓝队资产应保留同一造型，只替换可识别的队伍色区域。

- 队伍色占总可见面积约 `15%–30%`。
- 主体仍使用奶油色、木色、深灰等中性色。
- 不把红队物品做成整块纯红，也不把蓝队物品做成整块纯蓝。
- 功能色优先表达用途：冰冻仍用冰青色，火焰仍用黄橙色。
- 队伍色通常放在边框、底座、侧板、布条、指示灯外圈。

## 5. 建筑资产规范

### 5.1 外观

建筑是“玩具积木式农场厨房”，不是写实房屋。

- 墙体厚实，窗框和门框略微夸张。
- 使用暖奶油墙面、木色横梁和少量队伍色装饰。
- 屋顶采用简洁的大斜面，避免复杂瓦片。
- 厨房不完全封顶，确保第一人称和宣传摄像机能够看见内部。
- 建筑模块必须能以2m左右宽度重复拼接。

### 5.2 模块种类

基础模块：

```text
Wall
Door
Window
Roof
CornerPost
HalfWall
KitchenCanopy
Fence
```

模块接缝应通过柱子、边框或色块自然遮挡，不依赖完全无缝的贴图。

### 5.3 建筑材质

- 墙：暖奶油、低金属、高粗糙度。
- 木梁：中暖棕色，避免高光。
- 窗框：奶油色或队伍色。
- 玻璃：淡青色，透明度保持克制。
- 屋顶：暖红、蓝灰或木色，根据地图区域搭配。

玻璃建议：

- 不与墙面或窗框共面。
- 与框体沿法线至少错开 `0.01–0.025m`。
- Alpha不宜过低，避免排序错误。
- 第一版可以使用不透明淡蓝色玻璃代替真实透明。

### 5.4 模块拼接

- 尺寸使用固定网格，例如2m宽、2.5m高。
- 模块原点在底部中心。
- 左右边界必须明确，不让装饰越出拼接范围。
- 如果有边框，相邻模块需要决定“各有半框”或“仅模块自身完整框”，不能随机。

## 6. 食物资产规范

### 6.1 外观目标

食物需要看起来可爱、饱满、有食欲，但不追求真实纹理。

- 体积略大于现实比例。
- 使用2–5个大色块表达烘烤、汤汁、蔬菜和容器。
- 食物主体轮廓比餐具细节更重要。
- 不使用照片贴图、复杂液体模拟或真实油脂高光。

### 6.2 面包

- 主体为略不规则的圆角长方体或低边数椭圆体。
- 表面主色为暖金棕色。
- 顶部可有2–3条较浅切痕。
- 底部或侧面使用深棕色形成烘烤层次。
- 切痕必须是清晰大形，不能用细小贴图线。

### 6.3 汤和锅装食物

- 碗或锅使用8–12边圆柱。
- 汤面不得与碗内底面或装饰面共面。
- 汤面比碗沿低 `0.03–0.08m`。
- 蔬菜块使用4–8个大块体即可。
- 绿色汤使用叶绿、浅绿、奶油黄点缀。
- 黄色汤使用南瓜黄、玉米黄、橙色点缀。

### 6.4 菜谱可读性

不同菜谱不能只靠轻微颜色变化区分。至少改变一项：

- 容器。
- 主体轮廓。
- 顶部配料。
- 颜色组合。
- 蒸汽或旗签等大型识别点。

## 7. 农作物资产规范

### 7.1 植物结构

成熟作物通常由以下结构组成：

```text
Root/Stem
MainLeaves
FruitOrCrop
OptionalFlower
```

- 茎使用5–8边圆柱。
- 叶片用低顶点平面或压扁网格。
- 果实使用6–10边球体、圆柱或手工低模轮廓。
- 一株作物尽量不超过20个可见部件。

### 7.2 轮廓差异

每种作物必须从剪影上不同：

- 番茄：分叉植株 + 多个红色圆果。
- 玉米：高直茎 + 长叶 + 黄色玉米棒。
- 小麦：细长成束 + 顶部穗头。
- 西瓜：贴地藤叶 + 大型绿色圆果。
- 辣椒：小型枝叶 + 下垂细长红果。
- 草莓：贴地三叶 + 多个小红果。
- 茄子：较宽叶片 + 紫色下垂果实。
- 南瓜：贴地大叶 + 大型橙色分瓣果实。

不允许仅通过换颜色把同一模型冒充另一种作物。

### 7.3 颜色

- 茎和叶至少有深浅两种绿色。
- 成熟果实使用高饱和但不刺眼的颜色。
- 未成熟阶段应改变体积或轮廓，不能只把成熟果实染绿。
- 果实与叶片必须有足够明度或色相差。

### 7.4 风吹动画预留

如果植物需要 Shader 摇摆：

- 根部严格位于 `Z=0`。
- 不要把茎叶和根部完全合并成难以控制的巨大网格。
- 顶点颜色或局部高度可用于控制摆动权重。
- 根部顶点权重为0，顶部叶片权重接近1。
- 果实摆动幅度应小于叶片，避免像橡胶球。

## 8. 厨具和商店设备规范

### 8.1 外观

厨具是“玩具厨房设备 + 农场科技”：

- 粗壮主体。
- 大按钮、大把手、大锅口。
- 明确的放入食材区域和产出区域。
- 面板尽量使用几何色块，不依赖文字贴图。

### 8.2 类型识别

- 切菜台：宽平工作面 + 明显砧板。
- 锅：大型锅口 + 双侧把手。
- 烤箱：前门 + 大把手 + 顶部或侧面控制区。
- 冰柜：双门框 + 玻璃/冷藏门 + 竖直把手 + 冰雪标记。
- 商店机：屏幕 + 投入口/取货口 + 底座。

### 8.3 交互预留

GLB只负责视觉，不在模型内塞入逻辑节点。Godot场景另行添加：

```text
StaticBody3D
CollisionShape3D
InteractionArea
Marker3D
AudioStreamPlayer3D
```

开门、按钮或抽屉若以后需要动画，应作为独立语义对象，而不是与主体合并。

## 9. 工具与武器规范

### 9.1 外观原则

工具应更像夸张农具或厨房科技设备，而不是现代军械。

- 枪管短而粗。
- 握把厚实。
- 功能罐、种子仓、能量核心应成为主要轮廓。
- 不添加真实枪械商标、弹匣结构或精密机械内构。
- 第一人称视角下，主要颜色和功能部件必须清楚可见。

### 9.2 功能配色

| 工具 | 主色 | 结构色 | 功能色 |
|---|---|---|---|
| 播种炮 | 蓝绿色 | 深青灰 | 亮绿/种子黄 |
| 破坏炮 | 蓝紫色 | 深蓝灰 | 紫色 |
| 吸能枪 | 黄色 | 黑灰色 | 暖白/金黄 |
| 冰冻枪 | 深蓝色 | 深海军蓝 | 冰青色 |
| 火焰枪 | 红色 | 焦黑色 | 黄色/橙色 |
| 左轮 | 暖灰或木色 | 深石墨 | 铜色 |

### 9.3 功能轮廓

- 播种炮：大型透明或开窗种子仓、宽口喷洒头。
- 破坏炮：粗炮管、稳定支架、压缩能量室。
- 吸能枪：喇叭形吸入口、收束环、能量罐。
- 冰冻枪：横向冷却罐、冰青聚焦叉或冷却环。
- 火焰枪：黄色燃料罐、扩张喷口、橙色热源。

特效不应完全做进模型。粒子、光芒、炮弹和声音在 Godot 中实现。

## 10. 碰撞、重叠面与Godot导入禁区

本节是硬性要求，任何一项不满足都视为交付失败。

### 10.1 GLB不得包含可见碰撞壳

此前建筑闪烁的直接原因是：

- 可见模型 `SM_*` 与碰撞模型 `UCX_*` 占据完全相同的位置。
- Blender中的 `hide_render=True` 没有保证该对象不被 glTF 导出。
- Godot把 `UCX_*` 当作普通网格载入。
- 两层表面争夺同一深度，产生 Z-fighting 闪烁。

因此：

- 最终视觉 GLB 中不得存在 `UCX_*`、`MESH_UCX_*` 或其他碰撞网格。
- 不要假设 Blender 的隐藏、线框显示或关闭渲染会阻止 glTF 导出。
- 导出时只选择可见视觉根节点。
- Godot碰撞统一使用 `StaticBody3D + CollisionShape3D`。
- 简单资产可在 Godot 中使用 BoxShape3D、CapsuleShape3D 等基础形状。

导出前检查：

```python
for obj in bpy.context.scene.objects:
    upper_name = obj.name.upper()
    if upper_name.startswith(("UCX_", "MESH_UCX_")):
        raise RuntimeError(f"Collision mesh must not enter visual GLB: {obj.name}")
```

如果工作文件中必须保留碰撞对象，应建立独立 Collection，并在导出前明确排除，而不是只设置 `hide_render`。

### 10.2 禁止共面

以下结构经常产生闪烁：

- 墙面与装饰板完全共面。
- 窗玻璃与窗框背板共面。
- 汤面与碗底共面。
- 队伍色覆盖层与原始表面共面。
- 两个重复模型被放在相同位置。

处理方式：

- 沿表面法线错开至少 `0.005–0.025m`，具体取决于资产尺寸。
- 或删除被覆盖且永远不可见的底面。
- 或把装饰颜色合并进同一网格材质分区。

不要用极小的 `0.00001m` 偏移“碰运气”，远距离仍可能闪烁。

### 10.3 法线

导出前：

- 重新计算外侧法线。
- 检查负缩放镜像后的法线。
- 不使用重复面。
- 不保留内部重叠面。

```python
bpy.context.view_layer.objects.active = obj
obj.select_set(True)
bpy.ops.object.mode_set(mode="EDIT")
bpy.ops.mesh.select_all(action="SELECT")
bpy.ops.mesh.normals_make_consistent(inside=False)
bpy.ops.object.mode_set(mode="OBJECT")
```

如果当前 Blender 版本不支持该操作符，应使用 BMesh 等版本兼容方法。

### 10.4 透明与辉光

- 普通材质不要开启 Emission。
- 只有能量核心、指示灯可使用弱 Emission。
- 避免过强 Bloom/Glow 使整个物体泛白。
- 透明玻璃尽量少用；第一版可用不透明淡蓝材质。
- 多层透明面容易排序错误，不要制作双层贴合玻璃。

### 10.5 阴影

- 第一人称手持模型可在Godot中关闭投影，避免阴影穿过摄像机。
- 透明玻璃一般不需要投射实心阴影。
- 小型不可见内部件不应投射阴影。
- 建筑、树木和大型厨具保留阴影以建立空间层次。

| 资产类型 | 推荐三角面 |
|---|---:|
| 单株作物 | 100–600 |
| 单个食物 | 100–800 |
| 手持工具 | 300–1,500 |

| 建筑模块 | 100–1,500 |

- 不为不可见内部结构建模。
- 同一类别资产尽量共享材质。

- 静态资产不添加 Armature。
- 不使用 Subdivision Surface 制造最终高密度网格。
- 对大量重复作物，材质数量和 Draw Call 比单纯三角面更值得控制。

## 14. 自动验收流程

### 14.1 导出前

- 唯一根节点。
- 所有可见对象有语义名称。
- 无相机、灯光、测试地面。
- 无 `UCX_*` 或碰撞网格。
- 无零缩放、负缩放和极端坐标。
- 无重复对象。
- 无明显悬空部件。
- 主要材质不含意外 Emission。

### 14.2 重新导入GLB

必须在新的空场景中重新导入刚生成的GLB，并检查：

- 网格数量合理。
- 材质未丢失。
- 根节点和朝向正确。
- 包围盒尺寸正确。
- 不存在碰撞壳。
- 不存在零缩放。

示例验证：

```python
collision_meshes = [
    obj.name for obj in meshes
    if obj.name.upper().startswith(("UCX_", "MESH_UCX_"))
]
zero_scale = [
    obj.name for obj in meshes
    if min(abs(obj.scale.x), abs(obj.scale.y), abs(obj.scale.z)) < 0.000001
]

assert not collision_meshes
assert not zero_scale
```

### 14.3 预览图

至少输出一张 `1100×700` PNG：

- 3/4视角。
- 深灰或中性背景。
- 主光、补光、轮廓光。
- 完整模型进入画面。
- 能看到正面、侧面和顶部部分结构。

重点检查：

- 共面闪烁。
- 部件悬空。
- 颜色比例。
- 轮廓可读性。
- 朝向。
- 透明排序。

### 14.4 Godot验证

- 将GLB放入正确的 `assets` 子目录。
- 等待 Godot 生成 `.import`。
- 确认 `.godot/imported` 缓存存在。
- 在测试场景中观察静止画面和移动镜头。
- 确认没有闪烁面、异常辉光、透明排序或尺寸错误。
- 碰撞通过 Godot 原生节点单独制作。

## 16. 职业与角色方向

职业应围绕本游戏的五个核心行为建立：

```text
占领土地 → 种植收割 → 运送处理 → 烹饪交付 → 攻防干扰
```

不要只使用“农夫攻击低、厨师做菜快”这种纯数值区分。每个职业需要：

- 一个清楚的比赛职责。
- 一个能改变决策的主动能力。
- 一个容易被队友理解的视觉身份。
- 至少一种与土地、食材或厨房的互动特色。

### 16.1 拓荒手 / Seed Ranger

定位：土地争夺和规模化种植。

核心特点：

- 播种炮一次覆盖更多相邻土地。
- 占领中立土地速度更快。
- 能读取附近作物成熟度。
- 收割后短时间获得移动速度提升。

视觉：

- 大型背负种子罐。
- 青绿色短披肩或围裙。
- 宽口播种炮。

与原“农夫”的区别：不只是种地，而是前线扩张和土地控制角色。

### 16.2 灶台炼金师 / Flavor Alchemist

定位：菜谱连锁、烹饪和得分爆发。

核心特点：

- 能把相同食材做成不同效果的菜品。
- 连续正确完成菜谱获得“火候连击”。
- 可以临时加速一个厨具。
- 失败菜品不会完全损失，可转化为低分员工餐。

视觉：

- 大厨帽与护目镜组合。
- 腰间调味瓶。
- 锅铲或菜刀作为身份道具。

与原“厨师”的区别：强调配方、火候和组合策略，而不是单纯操作厨具。

### 16.3 跑堂员 / Pantry Runner

定位：高速物流、拾取、商店和救场。

核心特点：

- 搬运食材时减速更少。
- 可以同时标记两个配送目标。
- 在商店购买消耗品略有优惠。
- 能快速拾取散落果实，并将其投送到厨房共享库存。
- 可短暂冲刺，但携带高级菜品时冲刺会延长冷却。

视觉：

- 小型背篓或保温箱。
- 明亮围巾和路线标记。
- 轻便鞋和短围裙。

它是“助手”的特色化版本：不是哪里缺人去哪里，而是掌控全队物流节奏。

### 16.4 机关师 / Gadget Grower

定位：炮塔、护盾、冰冻、灼烧和设备维护。

核心特点：

- 放置自动炮塔和 ShieldDoor。
- 修复受损工具和厨房设备。
- 冰冻敌方设备，或用过载提高己方设备射速。
- 可以拆除并回收己方装置的一部分费用。

视觉：

- 工具腰带。
- 单眼护目镜。
- 队伍色机械手套。

该职业承接现在已经存在的炮塔、护盾和状态效果系统，容易形成明确玩法。

### 16.5 田野守卫 / Crop Warden

定位：保护土地、拦截炮弹和近距离击退。

核心特点：

- 吸能枪范围更大或持续更久。
- 可以给一小片己方土地施加短时保护膜。
- 使用橡胶弹或推力工具击退靠近厨房的敌人。
- 吸收炮弹后获得可用于护盾或反击的能量。

视觉：

- 宽檐草帽与护肩。
- 黄色能量罐。
- 粗壮吸能装置。

它不是传统坦克，而是围绕“保护作物和拦截投射物”的农场守门员。

### 16.6 捣蛋食客 / Kitchen Saboteur

定位：轻量干扰，不制造长时间失控。

核心特点：

- 使用烟雾调料短暂遮挡区域。
- 给敌方厨具增加短时间操作延迟。
- 能侦察对方当前菜谱和库存中的一种食材。
- 更擅长使用火焰枪、冰冻枪和橡胶左轮。

限制：

- 不应拥有长时间眩晕。
- 不可永久偷走高价值菜品。
- 干扰必须有明显预警和较短持续时间。

视觉：

- 歪厨师帽。
- 多口袋调料围裙。
- 紫橙色功能装饰。

### 16.7 菜谱侦察员 / Recipe Scout

定位：情报、地图标记和精准支援。

核心特点：

- 标记成熟作物、敌方装置和高价值食材。
- 一段时间内显示炮弹预计落点。
- 为队伍选择“今日推荐菜”，短期提高某类菜品得分。
- 可设置小型观察旗，但不直接造成高伤害。

视觉：

- 菜谱板与望远镜组合。
- 旗帜或地图卷筒。
- 蓝绿或黄绿轻装。

适合以后扩大到5v5时加入；第一版优先级低于机关师和跑堂员。

## 17. 推荐首发职业组合

如果每队只有2人，不建议强制锁定复杂职业。推荐：

```text
拓荒手 + 灶台炼金师
```

两人都保留基础拾取和搬运能力，避免一个人掉线后游戏无法继续。

如果扩展到4v4，推荐四个首发职业：

```text
拓荒手：土地和作物
灶台炼金师：烹饪和得分
跑堂员：运输和商店
机关师：炮塔、护盾和状态攻防
```

这个组合覆盖完整比赛循环，而且职责足够直观。

田野守卫可以作为第五个职业或机关师的分支。捣蛋食客和菜谱侦察员适合在核心循环稳定后再加入。

### 17.1 避免硬职业锁死

所有角色都应拥有：

- 拾取食材。
- 搬运基础物品。
- 使用基础交互。
- 在紧急情况下完成低效率播种或烹饪。

职业提供“更擅长”和“独特选择”，不应让队伍因为缺少某职业而完全无法种地或交付菜品。

### 17.2 角色轮廓区分

- 拓荒手：背部种子罐，横向宽轮廓。
- 灶台炼金师：高帽，纵向轮廓。
- 跑堂员：背篓和围巾，后部轮廓。
- 机关师：工具腰带和机械手套，侧面零件较多。
- 田野守卫：护肩和吸能罐，体型最宽。

即使所有角色共享基础身体模型，也可以通过帽子、背包、工具和围裙形成低成本差异。
